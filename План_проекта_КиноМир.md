# План разработки «КиноМир» — модульный Django-монолит каталога фильмов

## 1. Архитектура и структура проекта

«КиноМир» реализуется как учебный модульный монолит: один Django-проект, серверные Django Templates, одна SQLite3-база и статический frontend на Bootstrap 5 и обычном JavaScript. Отдельный REST API, React SPA, микросервисы и Docker для первой версии не используются.

Приложение хранит сведения о фильмах и ссылки на легальные внешние источники видео. Сами видеофайлы в SQLite не сохраняются. Постеры и баннеры загружаются через Django Admin в локальную папку `media/`.

Модели, формы, представления и тесты располагаются внутри приложения, которому принадлежит соответствующее поведение. Общей папки `utils` для бизнес-логики нет: поиск принадлежит `movies`, работа с профилем — `accounts`, общие настройки сайта — `core`.

- Backend: Python 3, Django 5.2 LTS, Django ORM, Django Authentication, Django Forms, Django Admin и Django Messages.
- Database: SQLite3 для локальной учебной эксплуатации.
- Frontend: Django Templates, HTML5, CSS3, Bootstrap 5, Bootstrap Icons и Vanilla JavaScript.
- Media: Pillow для изображений, HTML5 Video для прямых видеофайлов, `iframe` для разрешённых внешних проигрывателей.
- Дополнительные пакеты: `django-environ` для настроек и `django-filter` для фильтрации каталога.
- Тестирование: встроенные `django.test.TestCase`, `Client` и временные загружаемые файлы.

## 2. Доменная модель и бизнес-правила

- `User` — стандартный пользователь Django. Вход выполняется по `username`; email обязателен при регистрации и используется как контактное поле. Обычные пользователи не имеют доступа в Django Admin.
- `SiteSettings` — одиночная запись с названием «КиноМир», логотипом, текстом footer, контактами и SEO-описанием. Произвольный page builder и пользовательский HTML отсутствуют.
- `Genre` содержит название, уникальный `slug`, описание, изображение и признак активности.
- `Movie` содержит название, оригинальное название, `slug`, описание, год, страну, продолжительность, возрастное ограничение, режиссёра, актёров, жанры, постер, баннер, тип источника, URL видео и статусы публикации.
- Фильм может относиться к нескольким жанрам. Жанр может включать несколько фильмов.
- Только фильмы с `is_published=True` видны посетителям и участвуют в поиске, фильтрах и подборках.
- `is_featured=True` означает, что фильм может появиться в главном hero-баннере. Если отмечено несколько фильмов, используются последние по заданному порядку.
- `MovieSource` не выделяется в отдельную таблицу в первой версии: один фильм имеет один основной источник просмотра и необязательную ссылку на трейлер. Если позднее понадобятся разные озвучки или серии, источники выносятся в отдельную модель.
- `Favorite` связывает пользователя и фильм. Ограничение `UniqueConstraint(user, movie)` запрещает повторное добавление.
- `Rating` содержит целое значение от 1 до 5. Ограничения `CheckConstraint` и `UniqueConstraint(user, movie)` обеспечивают допустимый диапазон и одну оценку пользователя на фильм.
- Повторная отправка оценки изменяет существующую запись, а не создаёт новую.
- Средняя оценка вычисляется через `Avg` только по сохранённым оценкам. При отсутствии оценок интерфейс показывает «Нет оценок», а не `0.0`.
- `Comment` принадлежит пользователю и фильму, содержит текст, даты создания/изменения и признак `is_approved`.
- Публикуются только одобренные комментарии. Для учебной версии комментарий можно одобрять автоматически, но администратор всегда может его скрыть.
- Пустые комментарии запрещены. Максимальная длина текста — 1000 символов.
- Анонимный посетитель может просматривать каталог, карточки, страницы фильмов, оценки и комментарии.
- Только авторизованный пользователь может изменять избранное, ставить оценку и отправлять комментарий.
- История просмотров не создаётся. `views_count` означает количество открытий страницы фильма, а не персональную историю пользователя.
- Просмотр видео доступен со страницы опубликованного фильма. Приложение не обходит авторизацию, географические ограничения или запреты внешнего источника.
- Все добавляемые ссылки должны вести на контент, который разрешено публиковать или встраивать.

Основные типы видеоссылок:

- `direct` — прямая ссылка на `.mp4`, `.webm` или другой поддерживаемый браузером видеоформат;
- `youtube` — ссылка YouTube, преобразуемая в безопасный `youtube.com/embed/...`;
- `vimeo` — ссылка Vimeo, преобразуемая в `player.vimeo.com/video/...`;
- `iframe` — заранее разрешённый администратором источник для встраивания;
- `external` — внешняя страница, открываемая отдельной кнопкой.

Произвольный HTML в базе не хранится. Администратор вводит URL и выбирает тип источника; приложение само создаёт `<video>`, `<iframe>` или кнопку перехода.

## 2.1. Названные границы модулей

Три ключевые границы домена названы явно. HTTP-view, Django Admin, шаблоны и JavaScript только вызывают эти операции и не дублируют их правила.

### Catalog selector — модуль чтения в `movies/selectors.py`

Владеет публичным чтением каталога. Интерфейс:

- `published_movies()` — базовый QuerySet только опубликованных фильмов;
- `search_movies(query)` — поиск по названию, оригинальному названию, описанию, режиссёру и актёрам;
- `filter_movies(filters)` — жанр, год, страна и возрастное ограничение;
- `sort_movies(queryset, sort)` — новизна, название, рейтинг или популярность;
- `home_collections()` — hero, новинки, популярные и жанровые подборки;
- `similar_movies(movie)` — похожие опубликованные фильмы по общим жанрам.

За границей скрыты `select_related`, `prefetch_related`, `annotate`, `Q`, `Avg`, допустимые значения сортировки и защита от вывода неопубликованных объектов. View не собирают сложные ORM-запросы самостоятельно.

Порядок обработки каталога фиксирован:

```text
published_movies
    → search_movies
    → filter_movies
    → annotate рейтинга
    → sort_movies
    → Paginator
```

Некорректный фильтр не вызывает ошибку сервера: неизвестное значение игнорируется или форма показывает понятное сообщение. Размер страницы фиксирован, например 20 фильмов.

### Video resolver — модуль в `movies/video.py`

Владеет распознаванием и безопасным отображением источника. Интерфейс:

- `resolve_video(source_type, url)` — возвращает тип представления и нормализованный URL;
- `extract_youtube_id(url)` — извлекает идентификатор из обычных, коротких и embed-ссылок YouTube;
- `extract_vimeo_id(url)` — извлекает числовой идентификатор Vimeo;
- `validate_source(source_type, url)` — проверяет схему, домен и соответствие выбранному типу;
- `player_context(movie)` — готовит данные проигрывателя для шаблона.

Результат `resolve_video` имеет один из вариантов:

| Режим | Что отображает шаблон |
|---|---|
| `html5` | `<video controls>` с прямой ссылкой |
| `embed` | адаптивный `<iframe>` разрешённого провайдера |
| `external` | кнопка «Открыть источник» |
| `unavailable` | сообщение о недоступном источнике |

Resolver никогда не принимает готовый HTML и не помечает значение из базы как `safe`. Разрешены только `http` и `https`; опасные схемы `javascript:`, `data:` и `file:` запрещены. Для произвольного `iframe` применяется список разрешённых доменов. Если внешний сайт блокирует встраивание, используется режим `external`.

### Engagement service — модуль в `movies/services.py`

Владеет пользовательскими действиями. Интерфейс:

- `toggle_favorite(user, movie)` — добавляет или удаляет фильм и возвращает новое состояние;
- `set_rating(user, movie, value)` — создаёт либо обновляет оценку;
- `add_comment(user, movie, text)` — проверяет и создаёт комментарий;
- `delete_own_comment(user, comment)` — удаляет только собственный комментарий, если такая функция включена;
- `movie_rating(movie)` — средняя оценка и количество голосов.

Операции проверяют авторизацию и опубликованность фильма. Представления не делают `Favorite.objects.create()` или `Rating.objects.update_or_create()` напрямую. Все изменения выполняются POST-запросами с CSRF-защитой.

### Правила поверх трёх модулей

- Главная страница и каталог получают данные только через catalog selector.
- Страница фильма получает проигрыватель только через video resolver.
- Избранное, оценки и комментарии изменяются только через engagement service.
- Неопубликованный фильм возвращает 404 обычному пользователю, даже если известен его `slug`.
- Django Admin может просматривать неопубликованные фильмы, но публичные страницы не обходят общий selector.
- Средний рейтинг после изменения оценки пересчитывается запросом к базе; отдельное кэшированное поле в первой версии не хранится.
- Увеличение `views_count` выполняется атомарным `F()`-выражением, чтобы не терять параллельные обновления.
- GET-запросы ничего не добавляют, не удаляют и не изменяют, кроме технического счётчика открытия страницы фильма.

## 3. Интерфейсы, UI и административная панель

Приложение использует серверные HTML-страницы. Django формирует HTML через Templates, Bootstrap 5 отвечает за адаптивную сетку и компоненты, а небольшой JavaScript улучшает взаимодействие без обязательного SPA.

Публичные маршруты:

| Область | Маршруты и назначение |
|---|---|
| Главная | `GET /` — hero, новинки, популярные фильмы и подборки жанров |
| Каталог | `GET /catalog/` — поиск, фильтры, сортировка и пагинация |
| Жанр | `GET /genres/<slug>/` — опубликованные фильмы выбранного жанра |
| Фильм | `GET /movies/<slug>/` — детали, проигрыватель, рейтинг, комментарии |
| Поиск | `GET /search/?q=...` — результаты поиска с сохранением строки запроса |
| Регистрация | `GET/POST /accounts/register/` |
| Авторизация | `GET/POST /accounts/login/`, `POST /accounts/logout/` |
| Профиль | `GET /accounts/profile/` |
| Избранное | `GET /accounts/favorites/` |
| Действия | POST-маршруты избранного, оценки и комментариев |
| Admin | `/admin/` — управление содержимым |

GET-параметры каталога:

```text
/catalog/?q=matrix&genre=science-fiction&year=1999&country=USA&sort=rating&page=1
```

Допустимые значения `sort`:

- `newest` — сначала недавно добавленные;
- `year_desc` — сначала новые по году выпуска;
- `year_asc` — сначала старые;
- `title` — по алфавиту;
- `rating` — по средней оценке;
- `popular` — по `views_count`.

### Главная страница

Структура переносится из `шаблон.jpg`, а не копируется пиксель в пиксель:

1. компактная белая навигационная панель с логотипом «КиноМир»;
2. большой полноширинный hero-баннер выбранного фильма;
3. горизонтальная лента «Самые новые фильмы»;
4. секция «Сейчас популярно» с карточками и краткими описаниями;
5. широкий тёмный блок рекомендуемого просмотра с кнопкой воспроизведения;
6. подборки по жанрам;
7. footer с информацией об учебном проекте.

Основная палитра: белый фон, тёмный текст, оранжевый акцент, серые разделители и тёмный фон видеосекции. На мобильных устройствах меню переходит в Bootstrap Offcanvas, hero уменьшается, карточки выводятся по две в строке.

### Каталог

- строка поиска;
- фильтры по жанру, году, стране и возрастному ограничению;
- выбор сортировки;
- карточки с постером, названием, годом, жанрами и рейтингом;
- 20 фильмов на страницу;
- сохранение активных фильтров при переключении страниц;
- кнопка очистки фильтров;
- сообщение «По вашему запросу ничего не найдено».

### Страница фильма

- hero-баннер или затемнённый фон;
- постер;
- русское и оригинальное названия;
- описание, жанры, год, страна, продолжительность и возрастной рейтинг;
- режиссёр и актёры;
- средняя оценка и количество голосов;
- кнопка «В избранное»;
- адаптивный видеопроигрыватель или кнопка внешнего источника;
- форма оценки со звёздами;
- форма комментария;
- список одобренных комментариев;
- похожие фильмы.

### Регистрация и профиль

Форма регистрации содержит `username`, email, пароль и подтверждение пароля. Django валидирует уникальность имени, корректность email и надёжность пароля.

Профиль показывает:

- имя пользователя и email;
- дату регистрации;
- количество избранных фильмов;
- последние оценки;
- комментарии пользователя;
- ссылку на полный список избранного.

История просмотров отсутствует.

### Progressive enhancement и JavaScript

Основные функции работают через обычные Django-формы. JavaScript добавляет удобство:

- `fetch`-переключение избранного без полной перезагрузки;
- интерактивное выделение звёзд оценки;
- Bootstrap Toast после успешного действия;
- открытие мобильных фильтров;
- подтверждение удаления собственного комментария.

Если JavaScript отключён, POST-формы выполняют те же операции и перенаправляют пользователя обратно. Сервер остаётся единственным источником бизнес-правил.

### Формы и сообщения об ошибках

Django Forms отвечают за регистрацию, профиль, фильтры и комментарии. Ошибка выводится рядом с конкретным полем. Общие сообщения отображаются через Django Messages и Bootstrap Alert/Toast.

Примеры сообщений:

- «Вы успешно вошли»;
- «Фильм добавлен в избранное»;
- «Фильм удалён из избранного»;
- «Оценка сохранена»;
- «Комментарий отправлен»;
- «Необходимо войти в аккаунт»;
- «Источник видео недоступен».

### Django Admin

Администратор управляет `SiteSettings`, жанрами, фильмами, пользователями, оценками, избранным и комментариями.

Для фильмов настраиваются:

- миниатюра постера в списке;
- поиск по названию, оригинальному названию, режиссёру и актёрам;
- фильтры по публикации, жанру, году, типу источника и статусу hero;
- автоматическое заполнение `slug`;
- `filter_horizontal` для жанров;
- readonly-поля дат и `views_count`;
- admin actions «Опубликовать», «Снять с публикации», «Показать в hero»;
- проверка видеоссылки через общий video resolver.

Для комментариев доступны фильтры по статусу и действия «Одобрить»/«Скрыть». Оценка и пользователь у существующей записи не заменяются через публичный интерфейс.

Management-команда `seed_demo` идемпотентно создаёт:

- основные жанры;
- 8–12 демонстрационных фильмов;
- администратора из переменных окружения;
- тестового пользователя;
- настройки сайта.

Повторный запуск `seed_demo` обновляет или пропускает существующие записи и не создаёт дубликаты.

## 4. Локальный запуск и конфигурация

Для проекта создаётся отдельное виртуальное окружение Python. Основные зависимости фиксируются в `requirements.txt`:

```text
Django>=5.2,<6.0
Pillow
django-environ
django-filter
```

## 5. Проверка и критерии готовности

Тесты пишутся через публичные операции модуля, которому принадлежит поведение, и находятся рядом с ним.

### `movies/tests/` — каталог и модели

- неопубликованный фильм отсутствует в каталоге, поиске и жанровой странице;
- поиск находит русское и оригинальное название без учёта регистра;
- фильтры по жанру, году, стране и возрасту работают по отдельности и совместно;
- сортировки возвращают стабильный порядок;
- пагинация сохраняет GET-параметры;
- `Movie.slug` уникален;
- один фильм может принадлежать нескольким жанрам;
- средняя оценка и количество голосов рассчитываются корректно;
- `views_count` увеличивается атомарно;
- похожие фильмы не содержат текущий и неопубликованные фильмы.

### `movies/tests/` — video resolver

- обычные, короткие и embed-ссылки YouTube дают правильный embed URL;
- Vimeo-ссылки дают правильный player URL;
- прямые `.mp4` и `.webm` возвращают режим `html5`;
- внешний источник возвращает кнопку перехода;
- неизвестный или запрещающий встраивание домен не попадает в `iframe`;
- `javascript:`, `data:` и `file:` отклоняются;
- неверная ссылка не ломает страницу, а показывает состояние `unavailable`;
- пользовательский URL не превращается в произвольный HTML.

### `movies/tests/` — избранное, оценки и комментарии

- анонимный пользователь не может изменить избранное;
- повторное переключение удаляет фильм из избранного;

- повторная оценка обновляет прежнюю запись;
- средний рейтинг изменяется после обновления оценки;
- анонимный пользователь не может отправить комментарий;
- пустой и слишком длинный комментарии отклоняются;
- скрытый комментарий не виден публично;
- пользователь не может изменить или удалить чужой комментарий.

### `accounts/tests/` — пользователи

- успешная регистрация создаёт пользователя;
- дублирующий `username` или email отклоняется;
- слабый пароль не принимается;
- вход и выход работают через Django session;
- профиль и избранное защищены `login_required`;
- обычный пользователь не имеет доступа в Django Admin.

### `core/tests/` — главная и общие страницы

- главная страница открывается без авторизации;
- hero показывает только опубликованные отмеченные фильмы;
- новинки и популярные подборки имеют ограниченный размер;
- навигация содержит каталог, жанры, поиск и правильные кнопки авторизации;
- страницы 404 и 500 используют общий дизайн.

### Проверка HTML и интерфейса

- страницы используют семантические `header`, `main`, `section`, `article`, `nav` и `footer`;
- у изображений есть информативные `alt`;
- у полей есть `label`;
- кнопки доступны с клавиатуры;
- видимый `focus` не отключён;
- контраст текста достаточен;
- проигрыватель имеет `title` и адаптивное соотношение сторон;
- карточки не ломаются при длинных названиях;
- интерфейс корректен при ширине телефона, планшета и компьютера;
- пользовательские данные экранируются Django Templates.

### Ручные сценарии приёмки

1. Администратор входит в `/admin/`, создаёт жанр и фильм с прямой `.mp4`-ссылкой, публикует его; фильм появляется на главной и в каталоге.
2. Администратор добавляет фильм с YouTube или Vimeo; страница показывает встроенный проигрыватель.
3. Для внешней ссылки, которую нельзя встроить, страница показывает кнопку «Открыть источник» и не ломает макет.
4. Посетитель ищет фильм, применяет жанр и год, меняет сортировку и переходит на следующую страницу без потери фильтров.
5. Пользователь регистрируется, входит, добавляет фильм в избранное и видит его в профиле.
6. Пользователь ставит оценку, затем меняет её; в базе остаётся одна запись и обновляется средний рейтинг.
7. Пользователь отправляет комментарий; после одобрения администратора он отображается на странице фильма.
8. Неавторизованный посетитель пытается добавить фильм в избранное и перенаправляется на страницу входа.

Готовность подтверждается тем, что чистая установка по README завершается без ручной правки кода; миграции и `seed_demo` выполняются повторно; `python manage.py check` не выдаёт ошибок; все тесты проходят; главная, каталог, фильм, аккаунт и admin работают; интерфейс соответствует структуре `шаблон.jpg` и адаптируется под мобильный экран.

## Зафиксированные решения и отказы

- Архитектура — модульный Django-монолит, потому что проект учебный и не требует распределённой системы.
- Серверные Django Templates выбраны вместо React/Vue: интерфейс не нуждается в отдельном SPA, а авторизация, формы и SEO проще реализуются средствами Django.
- SQLite3 выбрана для локальной версии. Она не заявляется как база для неограниченного числа одновременных посетителей.
- Bootstrap 5 используется как CSS-фреймворк; собственный `style.css` адаптирует его под предоставленный макет.
- `django-filter` используется для явного описания фильтров, но сложные подборки и поиск остаются в catalog selector.
- Отдельный Django-app для рейтингов, комментариев и избранного не создаётся: эти сущности принадлежат взаимодействию пользователя с фильмом и остаются в `movies`.
- Отдельный API и Django REST Framework не вводятся: клиентом является Django Template, а небольшие `fetch`-запросы возвращают минимальный JSON.
- Отдельная модель видеоплеера не создаётся, пока у фильма один основной источник. Расширение до серий, сезонов и нескольких переводов потребует `MovieSource` или `Episode`.
- Общего пакета `utils` нет. Каталог, video resolver и пользовательские действия имеют конкретных владельцев.
- Средний рейтинг не сохраняется отдельным полем, чтобы не рассинхронизировать его с таблицей оценок.
- История просмотров сознательно отсутствует согласно требованиям.
- Реальные видеофайлы, транскодирование и потоковый сервер не реализуются. Приложение показывает разрешённые внешние источники.

## Зафиксированные ограничения

- Проект предназначен для локальной учебной демонстрации.
- Интерфейс и содержимое сайта — на русском языке.
- База данных — SQLite3.
- Один фильм имеет один основной источник просмотра и необязательный трейлер.
- Поддерживаются прямые видеофайлы, YouTube, Vimeo, разрешённые `iframe` и внешние страницы.
- Возможность встроить конкретный внешний сайт зависит от его политики; приложение не обходит запрет `iframe`.
- Нет истории просмотров, подписок, платного доступа, промокодов и реальных платежей.
- Нет самостоятельной загрузки фильмов пользователями.
- Нет персональных рекомендаций на основе поведения; похожие фильмы определяются по жанрам.
- Нет сериалов, сезонов и эпизодов в первой версии.
- Нет нескольких языков интерфейса.
- Нет email-подтверждения регистрации и восстановления пароля в обязательном объёме первой версии.
- Нет Docker и production-деплоя.
- Переход на PostgreSQL, объектное хранилище, CDN, Redis и production-сервер рассматривается только как возможное дальнейшее развитие.

## Итоговый результат

После выполнения плана получится учебное Django-приложение «КиноМир» с русскоязычным адаптивным интерфейсом, визуально основанным на `шаблон.jpg`. В приложении будут главная страница, каталог, жанры, поиск, фильтры, сортировка, пагинация, страницы фильмов, воспроизведение разных типов видеоссылок, регистрация, авторизация, личный кабинет, избранное, оценки, комментарии и Django Admin.

Проект будет достаточно простым для запуска, изучения и защиты, но ключевые границы — чтение каталога, обработка видеоссылок и пользовательские действия — будут отделены так, чтобы приложение можно было развивать без переписывания всей кодовой базы.
